# SINERGY SMM v1.1 Working Core

This layer replaces the v1.0 dataclass placeholders with a tenant-aware persistence and API core.

Implemented:

- JWT registration/login;
- workspace membership isolation;
- brands and Brand Brain knowledge;
- social-account schema with external secret references (never raw OAuth tokens);
- content calendar and persistent content items;
- omnichannel conversation/message schema;
- lead CRM and attribution fields;
- analytics events and overview API;
- deterministic Autopilot planning endpoint;
- official-integration connection entry points for VK/Meta plus Telegram/WhatsApp connection modes;
- Alembic migration bootstrap;
- API smoke tests;
- updated web Command Center;
- CI for backend tests and web build.

## Security boundary

OAuth authorization codes must be exchanged only by the backend. Resulting access/refresh tokens belong in a secret manager/KMS. `social_accounts.credentials_ref` stores only the reference to that secret. OAuth state must be persisted server-side before redirecting the user and validated once on callback.
